# /spec - Specifications

Define detailed requirements and implementation specifications.

## Quick Reference

- **User Story**: Who, what, why
- **Requirements**: Functional and design needs
- **Acceptance**: Success criteria
- **Components**: Which parts affected
- **Edge Cases**: What could go wrong
- **Dependencies**: Related features

## When to Use

- Before starting large features
- Complex requirements
- Design system additions
- API integrations
- Major component redesigns

## Common Tasks

```
/spec solar calculator input validation
/spec new service card component
/spec portfolio filtering feature
/spec contact form requirements
```

## Template

```markdown
# [Feature Name]

## User Story
As a [user], I want [action] so that [benefit].

## Requirements
- Requirement 1
- Requirement 2

## Success Criteria
- Criterion 1
- Criterion 2

## Components Affected
- Component A
- Component B

## Edge Cases
- Edge case 1
- Edge case 2
```
